Why Postfix Evaluation Works

In postfix notation, operators immediately follow their operands. When an operator is encountered, the stack already holds the necessary arguments. The result is pushed back, enabling sequential $O(n)$ evaluation in a single left-to-right pass.

postfix_evaluation.c C Logic
1for (int i = 0; postfix[i] != '\0'; i++) {
2 char c = postfix[i];
3 if (isdigit(c)) {
4 push(c - '0'); // Convert char to integer & push
5 } else {
6 int b = pop(); // Top operand
7 int a = pop(); // Next operand
8 switch(c) {
9 case '+': push(a + b); break;
10 case '-': push(a - b); break;
11 case '*': push(a * b); break;
12 case '/': push(a / b); break;
13 }
14 }
15}

Time Complexity: O(N)

Every character in an infix expression of length $N$ is pushed and popped at most once during conversion. Similarly, postfix evaluation scans the $N$-character string exactly once, performing constant $O(1)$ stack ops per token.

Space Complexity: O(N)

The auxiliary stack holds at most $N$ elements in the worst case (e.g. nested parentheses or sequential operands). The output string also requires $O(N)$ storage space.
